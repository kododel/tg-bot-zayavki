# Telegram-бот приёма заявок

Бот принимает заявки от клиентов по шагам, складывает их в базу и сразу
присылает менеджеру в Telegram. Менеджер ведёт заявки по статусам и в один
клик выгружает всё в Excel.

Решение для салонов, ремонтных и строительных бригад, служб доставки,
стоматологий и любых услуг, где заявки сейчас теряются в переписке.

---

## Что умеет

**Для клиента**
- пошаговое заполнение заявки: имя → телефон → описание задачи;
- телефон принимается в любом формате (`8 999 123 45 67`, `+7 (999) 123-45-67`);
- проверка ввода с понятными подсказками, а не «ошибка»;
- **номер проверяется на правдоподобие**: несуществующие коды и случайно
  набранные цифры отсекаются, а не превращаются в выдуманный номер;
- подтверждение перед отправкой, причём исправить можно **только номер**,
  не заполняя заявку заново;
- раздел «Мои заявки» со статусами.

**Для менеджера**
- мгновенное уведомление о новой заявке с телефоном и ссылкой на клиента;
- список заявок с фильтрами (новые / в работе / выполненные / отклонённые) и пагинацией;
- смена статуса в один клик прямо из карточки;
- статистика: всего, за сегодня, за 7 дней, по статусам;
- выгрузка всех заявок в Excel с фильтрами, автошириной колонок и отдельным листом со сводкой.

## Быстрый старт

### 1. Получить токен бота

Написать [@BotFather](https://t.me/BotFather) → `/newbot` → придумать имя и username →
скопировать токен вида `123456789:AAE...`.

### 2. Установить зависимости

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

Если установлен [uv](https://docs.astral.sh/uv/), всё то же самое быстрее:

```bash
uv venv && uv pip install -r requirements.txt
```

### 3. Заполнить настройки

```bash
cp .env.example .env
```

Открыть `.env` и вписать:

| Переменная | Что это |
|---|---|
| `BOT_TOKEN` | токен от @BotFather |
| `ADMIN_IDS` | ID менеджеров через запятую |
| `COMPANY_NAME` | название компании — подставляется в приветствие |
| `COMPANY_DESCRIPTION` | описание для раздела «О компании» |
| `MANAGER_CONTACT` | телефон/почта для прямой связи (необязательно) |

**Как узнать свой ID:** запустить бота и отправить ему `/id` — он покажет номер.
Вписать его в `ADMIN_IDS` и перезапустить бота.

### 4. Запустить

```bash
python -m bot.main
```

## Как устроено и почему так

**SQLite вместо PostgreSQL.** Поток заявок от одного-двух менеджеров — это десятки
записей в день. SQLite справляется с запасом, не требует установки и обслуживания,
и заказчик не платит за сервер. Включён режим WAL, чтобы чтение не блокировало запись.
Если заявок станет тысячи в день — слой БД изолирован, переезд на PostgreSQL
не затронет хендлеры.

**Секреты только в `.env`.** В коде нет ни токена, ни ID админов — проект
можно передать заказчику или выложить на GitHub, ничего не затирая.
`.env` в `.gitignore`.

**Доступ к админ-панели — фильтром на весь роутер.** Проверка `IsAdmin` навешена
на роутер целиком, а не на каждый хендлер: добавить новую админскую команду
и забыть про проверку доступа технически невозможно.

**Экранирование пользовательского текста.** Сообщения уходят в HTML-разметке,
поэтому весь ввод клиента проходит через `html.escape` — иначе клиент с именем
`<b>test` ломал бы сообщения менеджеру.

**Excel собирается в отдельном потоке.** `openpyxl` синхронный, и на большой базе
генерация файла заняла бы секунды; `asyncio.to_thread` не даёт боту замереть
и не отвечать остальным клиентам.

**Состояния диалога — в памяти.** `MemoryStorage` означает, что незавершённая
заявка сбрасывается при перезапуске. Для приёма заявок это нормально.
Нужны долгие сценарии — хранилище меняется на Redis одной строкой
в `bot/main.py`.

## Что можно доработать

Эти пункты — готовые направления для расширения бюджета проекта:

- **Приём заявок с сайта** — вебхук, который складывает заявки с формы в ту же базу.
- **Напоминания клиенту** — если менеджер не взял заявку в работу за N часов.
- **Несколько менеджеров с распределением** — заявки уходят по очереди или по городу.
- **Уведомления в WhatsApp/Email** параллельно с Telegram.
- **Хранение файлов** — клиент прикладывает фото или документ к заявке.
- **Админ-панель в браузере** — если нужны отчёты посложнее Excel.
- **Деплой на сервер** — systemd-юнит или Docker, автозапуск после перезагрузки.
